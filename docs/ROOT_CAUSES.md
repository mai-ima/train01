## 黒い帯(nd_road)の根本原因(2026-10-17)
- 現象: 構内道路(nd_road)が真っ黒な帯に写る。
- 根本原因: 道路の箱(上面 z=0.06)と下の敷地(nd_yard_cinder、上面 z=0.06)の上面が**同一平面で重なっていた**。Cycles は同一平面の二重面で影レイが自己交差し黒になる(Q17 の二重生成と同じ種類)。光量・材質の問題ではない。
- 対策: 重ねる面は必ず 0.02m 以上ずらす(道路を 0.09 に)。再発防止: Q3/Q18 の検査に「同一平面で重なる面」の検出を追加する(未実装→タスクQ3)。
- 追加(同日): 分岐・渡り線の交差部にあった黒い三角の欠けも同じ原因(各線のバラスト上面が同一高さで重なっていた)。trackkit.build_track でバラスト上面を線ごとに 2mm ずつずらす根本対策を入れ、撮影(d11d)で黒い欠けが消えたことを確認した。全駅の線路に効く。
- 検出器 DBG_COPLANAR(main.py)は外接箱ベースの粗い検査で、曲線軌道どうしの外接箱が重なるだけの誤検出が多い(穂波野で594組)。精密化(面単位の判定)が Q19 の残作業。
- Q19 検出器(2026-10-17): `DBG_COPLANAR=1 python3 main.py --zone <ID> --parts ...` で、薄い板どうしの上向き面が同一平面(差<0.004m)で重なる組を面単位で列挙する(main.py)。穂波野で 28 組(バラストは0組=対策が効いている)。残りはレール・枕木・継目板の分岐始端での重なり(1〜4面)で、分岐レールが本線レールと分かれ始める数十cmの区間に限られる。これは分岐器の構造上避けられないため許容し、黒欠けが出たら再検査する。
- Q18 再発防止(2026-10-17): main.py が毎回の構築後に「同位置・同頂点数の X/X.001」を数え、200組超で `[dup] failed: 二重生成の疑い` を出力する(healthscan の failed 検出対象)。正常時は30組前後(ミラー部品)、ZONE_PARTS=1 で意図的に二重生成させると 1492 組で警告が出ることを確認した。

## Q22 分岐器まわりの黒い楔(2026-10-17)
- 症状: 新車庫の入出庫線の分岐部で、枕木が見える真っ黒な細長い三角形が出る(上空・斜め視点)。Q19 の2mmオフセット対策後も残った。
- 切り分け: HIDE_OBJ(名前の前方一致で隠す)で N_leadX/N_leadB/N_toX を個別に隠しても消えず、`N_lead_`+`N_oldlead` を隠すと消え、`N_stab` を隠しても消えた → **N_lead と N_stab のバラスト上面が同じ高さで重なっていた**。
- 根本原因: Q19 の対策が `0.002 * (len(TRACKS) % 6)` で、**6本周期で同じオフセットが再発**した。線が12本以上ある構内では7本離れた線どうしが同一平面になり、影レイが自己交差して黒くなる。
- 対策: `0.012 * frac(n * 0.618…)`(黄金比数列)に変更。何本目でも互いに0.5mm以上離れる。上空・斜めの2視点で消失を確認(q22b)。
- 再発防止: 周期のあるオフセットを使わない。コプラナー検出(DBG_COPLANAR)は線が多い駅(M06・M01)でも定期的に回す。

## Q24 レンダごとに結果が変わる(hash() を乱数の種に使用)(2026-10-17)
- 症状: 同じコードでも実行ごとに枕木・金具・樹木の配置などが微妙に変わり、修正前後の比較(例: 黒い楔の有無)が乱数の影響を受ける。

- 対策: すべてのレンダ起動で `PYTHONHASHSEED=0` を設定する(scripts と実行例に追記)。新規コードでは hash() を使わず、名前から決まる固定計算(文字コードの加重和など)を使う。

## Q25 未定義の材質キーへの「静かなフォールバック」(2026-10-25)
- 症状: ① 踏切の取付道路が砂色の土の道(アスファルトのはずが) ② 全駅でホーム端の白線が描かれない ③ 国都中央の真鍮飾りが黒鉄、kit6 の銅板屋根が鉄板、干し草が暗い木色に置換

- 対策: common.make_materials() に white・brass・copper・yellow_grass を定義。踏切は写真ベースの ug_asph を直接使用。検出ツール `src/checks/matkeys_check.py` を追加(参照されているのに静的にも実行時にも定義が無いキーを列挙。現在 0 件)。

- 再発防止: 材質は `M["key"]` で直接参照して未定義なら KeyError で落とす書き方にする(`if key in M else` のフォールバックを新規に書かない)。大きな変更の後は matkeys_check.py を回す。
- 併せて: 生成結果に影響しうる無言の except 3か所(scenery.py の station_origin・struct_plan、veg.py の props.FOOT)を「…failed」付き出力にして healthscan の対象にした。
